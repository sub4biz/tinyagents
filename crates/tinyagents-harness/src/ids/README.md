# harness::ids

Identifier newtypes and lifecycle enums shared across the harness, plus the
dependency-free id-allocation primitives used to mint them.

## Why this exists

Every long-lived harness concept (runs, threads, calls, events, graph nodes,
checkpoints, interrupts, sessions, cells) is keyed by a small, cheap-to-clone
string newtype instead of a bare `String`. Wrapping the raw string prevents
accidentally passing, say, a `ThreadId` where a `RunId` is expected, and gives
every id a consistent `new`/`as_str`/`Display`/`From<&str>`/`From<String>`
surface generated by one macro (`impl_string_id!` in `mod.rs`).

These ids are also what makes recursion observable: a `RunId` names one run,
and pairing it with the `root_run_id`/`parent_run_id` recorded in
`crate::events::HarnessRunStatus` lets a child run (a sub-agent or sub-graph
invocation) be traced back up to the top-level run that spawned it.

## Public surface

- Id newtypes (`types.rs`): [`RunId`], [`ThreadId`], [`CallId`], [`EventId`],
  [`ComponentId`], [`GraphId`], [`NodeId`], [`TaskId`], [`SessionId`],
  [`CellId`], [`CheckpointId`], [`InterruptId`] — each gets `new`, `as_str`,
  `Display`, and `From<&str>`/`From<String>` via `impl_string_id!` in
  `mod.rs`.
- [`ExecutionStatus`], [`HarnessPhase`] (`types.rs`) — coarse lifecycle enums
  shared by direct model calls, agent loops, and graph-node invocations, both
  serde-encoded `snake_case`.
- Allocators (`mod.rs`): [`new_run_id`], [`new_checkpoint_id`],
  [`new_session_id`], [`new_cell_id`], [`new_call_id`] — mint fresh,
  process-unique (and, for run/checkpoint ids, restart-collision-free) ids.
- Shared primitives (`mod.rs`): [`next_seq`] (process-unique monotonic
  counter), [`process_nonce`] (per-process restart-uniqueness nonce),
  [`now_ms`] (the crate's single wall-clock-in-milliseconds convention).

## Files

| File       | Role                                                              |
| ---------- | ---------------------------------------------------------------------- |
| `types.rs` | Id newtype definitions, `ExecutionStatus`, `HarnessPhase`.             |
| `mod.rs`   | `impl_string_id!` macro instantiations, id allocators, sequence/nonce/clock primitives. |
| `mod_tests.rs`  | Unit tests: construction, `Display`/conversion round-tripping, serde encoding. |

## Operational constraints

- Id generation is deliberately dependency-free: no `rand`, no UUID crate.
  `next_seq` (a process-local `AtomicU64`) gives ordering within a process;
  `process_nonce` (seeded once from wall-clock nanoseconds) gives
  collision-freedom across a process restart. An id minted from `next_seq`
  alone would restart at the same values after every process restart.
- `new_checkpoint_id`'s restart-safety is load-bearing, not cosmetic:
  checkpoint ids key the parent-lineage spine that graph pruning, history
  listing, and `ResumeTarget::Checkpoint` all walk. A duplicate checkpoint id
  across a restart can delete a live record's ancestor or resume the wrong
  checkpoint.
- `now_ms` is the crate's single millisecond-timestamp convention (epoch,
  saturating to `0` before the epoch). Reuse it rather than re-deriving a
  timestamp locally, so every timestamped record in the crate agrees on the
  convention.
- Each id newtype wraps a `pub(crate) String` — external code cannot construct
  one from a raw field access, only through `new`/`From`, which keeps the
  newtype boundary meaningful outside the crate.
